# AGENTS.md — PlaceForge / gebeta-geocoding

## Go module path

The repo is named "PlaceForge" but the Go module is `github.com/abenezer/gebeta-geocoding`. Always use the Go module path for imports, never the directory name.

## Build

```pwsh
# Builds for linux/amd64, outputs bin/main
make build-linux

# Or directly:
go build -o bin/main ./src
```

There is no `go run` shortcut configured. Entrypoint is `src/main.go`.

## Database: Prisma schema, sqlx runtime

**Prisma is used only for schema definition and migration management.** The Prisma client is NOT used at runtime. All queries in repositories use raw SQL via `jmoiron/sqlx` with the `lib/pq` PostgreSQL driver.

Schema lives under `src/db/model/` (files: schema.prisma, core.prisma, operations.prisma).

### Prisma commands (from Setup.md)

```pwsh
go run github.com/steebchen/prisma-client-go generate --schema ./src/db/model
go run github.com/steebchen/prisma-client-go migrate dev --schema ./src/db/model
go run github.com/steebchen/prisma-client-go migrate deploy --schema ./src/db/model
go run github.com/steebchen/prisma-client-go format --schema ./src/db/model
```

### Required PostgreSQL extensions

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;
```

### DB connectivity

- Single `sqlx` connection pool, stored globally as `db.DBConnections` (a slice).
- `db.ReturnRandomConnection()` and `db.ReturnMasterConnection()` for access.
- Every repository function takes `db *sqlx.DB` as first parameter after context.
- Connection strings come from `POSTGRES_URLS` env var (comma-separated DSNs).
- No user setup required during development — see `Setup.md` for provisioning commands.

## HTTP router: go 1.22+ net/http, NOT chi

Despite the README mentioning "chi route registration", the code uses **Go 1.22+ standard library `http.ServeMux`** with method-and-path patterns like `"POST /ingests/"`. Do NOT import chi.

## Module registration

Four modules, registered in `src/modules/main.router.go:29-35`:

1. **data-quality** — `/flags`, `/completeness-rules`, `/deltas`, `/merges`
2. **ingest** — `/ingests`, `/channels`, `/cursors`, `/schemas`, `/dlq`
3. **worker** — `/workers`, `/instances`, `/runs`
4. **business** — `/claims` (NOT documented in README — place ownership claims)

Each module exposes `func RegisterRoutes(mux *http.ServeMux)` in its `api/v1` package.

## Handler pattern

All HTTP handlers return `error` and are wrapped via `apiUtils.HandleError(handler)`. Do NOT write handlers with the standard `(w, r)` signature — always return `error`.

```go
func MyHandler(w http.ResponseWriter, r *http.Request) error { ... }
```

## RabbitMQ broker: separate from main server

RabbitMQ connections are NOT started in `main.go`. The broker layer has two standalone CLI tools:

- `src/broker/model/constructor.go` — code-generates `definition.go` from `topologies.json`
- `src/broker/model/chore/definer.go` — declares/tears down exchanges, queues, bindings on the broker

Topology definition: `src/static/internal/broker/topologies.json`. Regenerate `definition.go` after topology changes.

## Auth is stubbed

`src/api/utils/auth.go` has all authentication logic commented out. Requests pass through unauthenticated. Do not rely on auth middleware for anything.
